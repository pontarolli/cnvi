Por que expandir o sistema de arquivos?

  • O Raspberry Pi Imager grava a imagem do sistema no tamanho mínimo necessário, não no tamanho total do cartão
  • Sem expandir, sobra pouco espaço livre pra pacotes, imagens Docker e containers
  • É um passo único, feito uma vez por nó

Roteiro prático — conectar e expandir

  1. Conectar via SSH: ssh pi@rpi-10X (senha 147)
  2. Abrir o utilitário de configuração: sudo raspi-config
  3. Menu 6 Advanced Options → A1 Expand Filesystem
  4. Confirmar e reiniciar: sudo reboot

Nota

Depois do reboot, a conexão SSH cai — é esperado. Esperem alguns segundos e reconectem com o mesmo comando de antes.

Roteiro prático — atualizar o sistema

  1. Reconectar via SSH depois do reboot
  2. Atualizar a lista de pacotes disponíveis: sudo apt update
  3. Atualizar os pacotes já instalados: sudo apt upgrade -y

Nota

O upgrade pode demorar alguns minutos num Raspberry Pi 3B+. Aproveitem a espera pra revisar a ficha do grupo ou o repositório no GitHub.

Roteiro prático — instalar o Docker

Script oficial de instalação (funciona também no Raspberry Pi OS):

curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

Conferir se instalou:

docker --version

Rodar Docker sem sudo

  • Por padrão, só o root (ou quem usa sudo) consegue falar com o daemon do Docker
  • A solução não é dar privilégio de administrador total ao usuário (grupo sudo) — isso libera muito mais do que o necessário
  • O grupo certo pra isso é o grupo docker: quem está nele conversa com o Docker sem sudo, mas continua sem privilégio de root no resto do sistema

Nota

Reparem na diferença: grupo sudo = administrador do sistema inteiro. Grupo docker = só fala com o Docker sem digitar sudo toda hora. É o segundo que resolve o incômodo de ficar digitando sudo docker ....

Roteiro prático — grupo docker

  1. Adicionar o usuário pi ao grupo docker:
sudo usermod -aG docker pi
  1. Sair e reconectar via SSH — o grupo novo só vale numa sessão nova:
exit
ssh pi@rpi-10X
  1. Conferir, sem sudo:
docker run hello-world

Roteiro prático — Docker Compose

Verificar se o plugin já veio junto com a instalação do Docker:

docker compose version

Se não existir, instalar o plugin:

sudo apt install docker-compose-plugin -y

Nota

Reparem que é docker compose (subcomando, sem hífen) — é o padrão atual. O antigo docker-compose (com hífen, um programa separado) está em desuso.

Por que usar docker-compose.yml desde já

  • Um comando docker run longo é fácil de esquecer ou digitar errado da próxima vez — e some do histórico se ninguém anotar
  • Um arquivo docker-compose.yml documenta exatamente o que foi subido, com todas as opções — e fica salvo, versionado, no repositório do grupo
  • A partir de hoje, todo container do projeto sobe por um arquivo docker-compose.yml, não por comando avulso no terminal — um arquivo por serviço, cada um na sua própria pasta

Por que instalar o Portainer

  • Nas próximas aulas os grupos vão lidar com containers o tempo todo (broker MQTT, microsserviço etc.)
  • Gerenciar tudo só por linha de comando (docker ps, docker stop, docker start…) atrapalha quem está começando agora
  • O Portainer dá uma interface web simples: iniciar, parar e olhar containers sem decorar comando nenhum

Portainer: um por nó, não um cluster

  • Existe um modo mais avançado (Portainer Agent) pra gerenciar vários Raspberry Pi a partir de um único Portainer central — envolve rede entre agentes, certificados, mais configuração
  • Não vamos usar isso agora — cada Raspberry Pi roda o seu próprio Portainer, cuidando só dos containers dele mesmo
  • É o suficiente pro que precisamos hoje: ligar/desligar containers de forma gráfica, sem complicação extra

Nota

Como o nó é compartilhado, o Portainer de cada Raspberry Pi vai mostrar os containers de todos os grupos que usam aquele nó, não só os seus. Mexam apenas nos containers com o prefixo do próprio grupo (mesmo nome do veículo usado na ficha e nos tópicos MQTT).

Container de teste: Node-RED em vez de um descartável

  • Em vez de subir algo só pra testar e apagar em seguida (como um Nginx de exemplo), já deixamos rodando o Node-RED
  • É uma ferramenta de fluxos visuais muito usada em projetos de IoT — o projeto provavelmente vai usar de verdade mais pra frente, pra tratar as leituras que chegarem via MQTT
  • Ou seja: o “teste de hoje” já fica útil, em vez de descartável

Roteiro prático — pastas do projeto

  1. Criar uma pasta pro projeto, com uma subpasta por serviço:
mkdir -p ~/fiscalizacao/portainer ~/fiscalizacao/node-red
  1. Cada serviço vai ter seu próprio docker-compose.yml, isolado na sua pasta — não um arquivo único com os dois

docker-compose.yml — portainer

cd ~/fiscalizacao/portainer && nano docker-compose.yml — colar o conteúdo abaixo, salvar com Ctrl+O, Enter e sair com Ctrl+X:

services:
  portainer:
    image: portainer/portainer-ce:latest
    container_name: portainer
    restart: always
    command: --admin-password '$$2b$$10$$7nPyOAsha7uiMAeA55/6Z.muRIi5.jf8G7JPteVN9OtdIDuSS6vS2'
    ports:
      - "8000:8000"
      - "9443:9443"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - portainer_data:/data

volumes:
  portainer_data:

docker-compose.yml — sobre o --admin-password

Nota

Não precisam entender essa linha pra usar — só o login importa: usuário admin, senha 147258369147 (próximo slide). O texto gigante no comando é só uma versão criptografada dessa senha, que o Portainer exige nesse formato específico. Com isso ele já sobe pronto pra login direto, sem tela de criar administrador nem token no log.

docker-compose.yml — node-red

cd ~/fiscalizacao/node-red && nano docker-compose.yml — colar o conteúdo abaixo, salvar com Ctrl+O, Enter e sair com Ctrl+X:

services:
  node-red:
    image: nodered/node-red:latest
    container_name: node-red
    restart: always
    ports:
      - "1880:1880"
    volumes:
      - node_red_data:/data

volumes:
  node_red_data:

Roteiro prático — subindo com Docker Compose

cd ~/fiscalizacao/portainer && docker compose up -d
cd ~/fiscalizacao/node-red && docker compose up -d

Conferir os dois juntos (docker compose ps só mostra os containers da pasta atual):

docker ps

Nota

Cada pasta é um projeto Compose independente. Pra derrubar um serviço sem afetar o outro, sem apagar os dados: entrar na pasta dele e rodar docker compose down.

Roteiro prático — acessando Portainer e Node-RED

  • Portainer: https://rpi-10X:9443 — HTTPS com certificado próprio, o navegador vai avisar que “não é seguro”; cliquem em Avançado → Continuar mesmo assim
  • Node-RED: http://rpi-10X:1880

No Portainer, façam login direto (sem tela de cadastro nem token):

  • Usuário: admin

Selecionem o ambiente local — é o próprio Docker do Raspberry Pi. Na aba Containers dá pra iniciar, parar, reiniciar e ver logs com botões, sem digitar nada.

Salvando o trabalho no repositório do grupo

  • Façam o commit dos dois arquivos docker-compose.yml (pasta portainer/ e pasta node-red/) no repositório do grupo (ex.: dentro de raspberrypi/)
