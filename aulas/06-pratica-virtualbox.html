Aula 06 — Prática: VirtualBox

Computação em Nuvem e Virtualização

Ricardo Pasquati Pontarolli

Técnico em Redes de Computadores · IFSP Boituva · pasquati@ifsp.edu.br · v42

Objetivos da aula

  • Instalar e configurar o Oracle VirtualBox
  • Criar uma máquina virtual do zero
  • Instalar um sistema operacional Linux (Ubuntu) na VM
  • Explorar componentes virtuais na prática (vCPU, vRAM, disco virtual)

Aula 100% prática — reservar o laboratório de informática. Verificar com antecedência se as máquinas suportam virtualização por hardware (VT-x/AMD-V habilitado na BIOS).

Antes de começar

Nota

Checklist:

  • VirtualBox instalado (ou baixar de virtualbox.org)
  • Imagem .iso do Ubuntu Desktop baixada (ou Lubuntu/Xubuntu se o PC for mais fraco)
  • Pelo menos 25 GB de espaço livre em disco
  • Virtualização por hardware habilitada na BIOS (VT-x / AMD-V)

Passo 1 — Criar a VM

  1. Abrir o VirtualBox → Nova
  2. Nome: ubuntu-lab | Tipo: Linux | Versão: Ubuntu (64-bit)
  3. Memória (vRAM): 2048 MB (mínimo recomendado)
  4. Criar um disco virtual agora → VDI → alocado dinamicamente (thin provisioning) → 20 GB

Relacionar com a Aula 05: aqui o aluno está literalmente configurando vCPU, vRAM e disco virtual que acabou de estudar na teoria.

Passo 2 — Ajustar configurações da VM

  • Sistema → Processador: definir 2 vCPUs (se o host tiver 4+ núcleos)
  • Sistema → Placa-mãe: habilitar EFI (opcional, para Ubuntu recente)
  • Armazenamento: montar a .iso do Ubuntu na unidade óptica virtual
  • Rede: manter modo padrão (NAT) para ter acesso à internet dentro da VM

Passo 3 — Instalar o sistema operacional

  1. Iniciar a VM → ela vai “bootar” a partir da .iso do Ubuntu
  2. Seguir o instalador gráfico do Ubuntu normalmente (idioma, teclado, usuário, senha)
  3. Aguardar a instalação (pode levar alguns minutos)
  4. Reiniciar a VM (ejetar a .iso quando solicitado)

Passo 4 — Explorar a VM

Depois de instalado, dentro da VM:

  • Abrir o terminal e rodar htop ou top — reparar que ele mostra “2 CPUs”, que são as vCPUs configuradas
  • Rodar free -h — conferir que a RAM mostrada é a vRAM configurada (2 GB), não a RAM real do computador físico
  • Rodar df -h — conferir que o disco mostrado é o disco virtual (20 GB), não o disco real

Isso é a prova prática de que o sistema operacional “acredita” que está rodando em hardware real — mas está isolado, sobre um hipervisor Tipo 2.

Passo 5 — Snapshot (fotografia da VM)

  1. Com a VM ligada e o sistema já configurado, ir em Máquina → Fazer Snapshot
  2. Dar um nome, ex.: ubuntu-limpo
  3. Fazer alguma alteração na VM (instalar um programa, criar um arquivo)
  4. Restaurar o snapshot e verificar que a alteração desapareceu

Conecta diretamente com o conceito de “snapshot e rollback” visto na Aula 05 como benefício das VMs.

Atividade avaliativa

Individualmente, entregar com prints:

  1. Print da tela de configuração da VM (vCPU, vRAM, disco)
  2. Print do terminal dentro da VM rodando htop, free -h e df -h
  3. Print do snapshot criado e da restauração funcionando
  4. Um parágrafo respondendo: qual a diferença entre o que o htop mostra dentro da VM e o Gerenciador de Tarefas do computador físico (host)?

Síntese da aula

  • Criamos uma VM real, configurando na prática vCPU, vRAM e disco virtual
  • Vimos que o SO dentro da VM enxerga apenas os recursos virtuais, isolados do hardware físico real
  • Snapshots permitem voltar a um estado anterior da VM rapidamente
